# 独立评审指南

本文提供稳定的评审方法，不记录某个版本的通过结论、测试数量或机器状态。评审必须以目标
commit、当前工作区和新鲜命令输出为准。

## 评审前先固定范围

记录以下信息：

- 目标分支和完整 commit；
- 与哪个基线比较；
- 评审是只读还是包含修复授权；
- 是否允许真实 OAuth、订阅额度调用或外部写入；
- 明确的非目标和停止条件。

历史聊天、旧交接和发布说明只能作为线索，不能替代当前文件与 Git 证据。

## 推荐阅读顺序

1. `AGENTS.md`：确认角色、权限和门禁。
2. `docs/README.md`：按变更类型选择文档。
3. `docs/DESIGN.md`：判断改动是否越过产品和分层边界。
4. `docs/UPSTREAM.md`：核对 Codex wire 行为是否有证据。
5. 目标 diff、受影响实现和对应测试。
6. `docs/MAINTENANCE.md`：核对文档影响与验证要求。

## 核心检查清单

### 运行正确性

- 请求在写出响应前后的错误处理是否正确；
- 流式终止、背压、取消和监听器清理是否完整；
- 非流式聚合是否只在终止事件后完成；
- 401 刷新重试是否有界，且不会重复写出响应；
- 并发刷新是否保持单飞和锁内二次判断。

### 协议边界

- Codex 私有细节是否仍被隔离在 `src/upstream/` 和 `src/auth/`；
- 是否新增未经证实的参数改写、模型白名单或客户端特判；
- 明确不支持的 OpenAI 参数是否稳定报错，而不是静默丢弃；
- 所有 wire workaround 是否在 `docs/UPSTREAM.md` 有原因和证据。

### 安全与隐私

- token、Authorization、OAuth code/state 和凭证路径是否可能进入日志或响应；
- 凭证写入是否继续保持原子性和平台权限约束；
- 非 loopback 监听是否仍有清晰警告；
- 测试、fixture、提交历史和文档中是否出现真实凭证或个人信息。

### 测试与文档

- 行为变化是否先由失败测试覆盖；
- 单元、契约测试是否覆盖成功和失败路径；
- `README.md`、`DESIGN.md`、`UPSTREAM.md`、`MAINTENANCE.md` 和示例是否按影响同步；
- 是否运行 `pnpm doc-check`，并完成人工语义核对。

## 默认验证命令

```bash
pnpm test
pnpm typecheck
pnpm build
pnpm doc-check
git diff --check
```

真实调用不是默认评审步骤。只有 `DECISION_OWNER` 明确授权时，才运行
`doctor --live`、`pnpm test:live` 或 `scripts/probe-*.ts`。

## 严重度

- `P0`：凭证泄漏、破坏性行为或大范围不可用，必须立即停止。
- `P1`：核心契约、运行正确性或发布门禁失效，修复前不能放行。
- `P2`：在合理条件下影响功能、维护性或诊断质量，应在发布前处理或明确接受。
- `P3`：低风险清晰度、测试或文档问题，不应夸大为阻断项。

## 评审输出

每条发现应包含：严重度、文件和行号、触发条件、实际影响、证据、建议动作。先列发现，
再给总体结论和剩余风险。没有发现时也要说明检查范围、已运行验证和未验证内容。

评审者默认只读，不应把发现静默变成自己的实现任务；实现者也不能作为唯一评审者自行判定通过。
